# پذیرش دفتر مورگیج

این سناریوها با داده‌های ساختگی اجرا می‌شوند. هیچ state واقعی کاربر، پروفایل شخصی مرورگر یا دادهٔ بازی در مخزن قرار نمی‌گیرد.

## اجرای تکرارپذیر

```sh
npm ci
npm test
npm run build
npx playwright install chromium
npx playwright test
npx playwright test --browser=webkit --grep "complete mobile flow at 390|transfer keeps card identity"
```

Playwright روی خروجی تولیدی `dist` و سرور `vite preview` در پورت ۴۱۷۳ اجرا می‌شود. برای آزمایش نسخهٔ منتشرشده، `PLAYWRIGHT_BASE_URL` را برابر آدرس واقعی همان نسخه قرار دهید؛ هر تست یک context مرورگر تازه دارد. مجموعهٔ کامل با Chromium اجرا می‌شود؛ فرمان جداگانهٔ WebKit دو مسیر اصلی انتقال و موبایل را اجرا می‌کند و به نصب همان مرورگر با `npx playwright install webkit` نیاز دارد. این اجراها تست گوشی فیزیکی محسوب نمی‌شوند. اگر WebKit جدا اجرا نشده باشد، سازگاری آن را تأییدشده گزارش نمی‌کنیم.

برای Preview محافظت‌شدهٔ همین پروژه، حالت اختیاری `VERCEL_PREVIEW_TEST=1` از OIDC توسعهٔ موجود در `.env.local` نادیده‌گرفته‌شده استفاده می‌کند. هدر فقط به origin دقیق `PLAYWRIGHT_BASE_URL` افزوده می‌شود و trace در این حالت خاموش است. تست Production به این حالت یا هدر نیاز ندارد. فایل محیطی و token هرگز در خروجی تست یا مخزن قرار نمی‌گیرند.

## سناریوهای مرورگر

- بردار مستقل از پیاده‌سازی برای کارت ۲۰۰: ۱۰۰، ۱۱۰، ۱۲۱، ۱۳۳، ۱۴۶، ۱۶۱، ۱۷۷، ۱۹۵، ۲۱۴؛ بهره فقط برای کارت‌های فعال صاحب همان دور.
- کارت تازه از دور صفر؛ تسویهٔ مستقل، مبلغ پرداخت ثابت و حفظ آن پس از reload.
- انتقال کارت با بدهی ۱۲۱، شناسهٔ ثابت، دور بی‌اثر صاحب قبلی و بدهی ۱۳۳ با اولین دور صاحب جدید.
- قیمت فرد ۲۰۱ با دریافت ۱۰۱ و دور اول ۱۱۱؛ شروع مزایدهٔ ۱۵۰، ۲۰۱ و ۲۰۲ به‌ترتیب ۳۸، ۵۰ و ۵۱.
- چند آخرین شانس مستقل، توقف دور صاحب، انتقال همان وضعیت و محدودیت، تصمیم مستقل تسویه یا مزایده و سابقهٔ مزایدهٔ بسته.
- قیمت بسیار کوچک با بدهی نمایشی برابر قیمت و عبور دقیق از سقف، همراه توضیح گردکردن.
- نام‌گذاری پیوسته بدون افت focus/caret؛ هماهنگی selector صاحب و انتقال؛ تفکیک نام‌های تکراری.
- Undo معکوس نام، ثبت، دور، انتقال و تسویه؛ حفظ Undo بعد از reload؛ دوبار کلیک ناخواسته و کلیک تازه بلافاصله پس از Undo.
- دانلود واقعی JSON، import با تأیید، بازی جدید با حفظ نام و بایگانی، لغو تأیید و بازیابی آرشیو.
- مهاجرت کلید قدیمی با active/grace/settled/auction، حفظ raw laps و زمان نامعلوم؛ refresh بدون مهاجرت دوباره و تقدم دفتر جدید.
- بازی تاریخی `legacy-simple`: برابری در دور ۱۰ فعال و عبور strict در دور ۱۱؛ بازی تازه همیشه مرکب.
- JSON خراب، نسخهٔ ناشناخته، مالک نامعتبر، شناسهٔ تکراری و bounds؛ ورودی‌های عدد نامعتبر دادهٔ سالم را تغییر نمی‌دهند.
- متن شامل HTML به‌صورت متن نمایش داده می‌شود و کد اجرا نمی‌کند.
- دو تب، رد تغییر مبتنی بر نسخهٔ قدیمی و خواندن صریح نسخهٔ جدید؛ قفل ویرایش در خواندن ناهم‌زمان نسخهٔ تازه؛ context مستقل با دفتر مستقل.
- خطای مصنوعی QuotaExceededError هنگام put در IndexedDB، حفظ snapshot سالم، پیام روشن و retry بدون تکرار کارت یا دور.
- دادهٔ ذخیره‌شدهٔ خراب خودکار با بازی خالی overwrite نمی‌شود.
- مسیر کامل در عرض‌های ۳۶۰، ۳۹۰ و ۴۳۰ شامل نام فارسی، رقم فارسی/عربی، انتقال، تسویه، Undo، خروجی/بازیابی و reload؛ بدون overflow افقی یا خطای console.
- صفحهٔ باز بدون شبکه همچنان ثبت می‌کند؛ پس از آماده‌شدن worker، قطع شبکه و reload واقعی؛ نصب worker تازه و حفظ دفتر و ورودی ثبت‌نشده.

## ثبت نتیجه

ادعای موفقیت فقط پس از اجرای فرمان و مشاهدهٔ نتیجه معتبر است. شمار تست‌های موفق/ناموفق، محدودیت مرورگر، build و آزمایش Preview/Production در `STATUS.md` ثبت می‌شود. این فایل فهرست قرارداد و فرمان اجرای آن است و به‌تنهایی شاهد اجرای تست نیست.
