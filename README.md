# دفتر مورگیج مونوپولی

[بازکردن برنامه](https://mortgage-monopoly.vercel.app/)

دفتر فارسی برای یک اداره‌کننده و هشت بازیکن در بازی حضوری. نام‌ها را روی جایگاه‌ها بنویس، صاحب و نام و قیمت کارت را وارد کن و «بذار مورگیج» را بزن. «دور زد» فقط یک دور کامل همان بازیکن روی صفحهٔ بازی است.

## تاریخچه و اصلاح کارت

روی هر کارت، «تاریخچهٔ کارت» ثبت اولیه، دورها، انتقال، تسویه، مزایده و اصلاح را با مبلغ و نام بازیکن در همان لحظه نشان می‌دهد. کارت‌های تسویه‌شده و مزایده‌های بسته هم این کنترل را در سوابق دارند.

با «اصلاح اسم و قیمت» مشخصات را تغییر بده؛ پیش‌نمایش، بدهی جدید را پیش از ذخیره نشان می‌دهد. شناسه، صاحب، تعداد دورها و وضعیت کارت حفظ می‌شوند. مثال: کارت ۲۰۰ بعد از دو دور بدهی ۱۲۱ دارد؛ اصلاح قیمت به ۳۰۰، با همان دو دور، بدهی را ۱۸۲ می‌کند. مبلغ تسویهٔ قبلاً ثبت‌شده، زمان و صاحب پرداخت ثابت می‌مانند. هر اصلاح یک اقدام است؛ «برگردون» مشخصات و تاریخچه را با هم به قبل از اصلاح برمی‌گرداند.

دفترهای قبلی خودکار و بدون پاک‌شدن داده به‌روز می‌شوند. چون نسخهٔ قبلی جزئیات رویدادها را نگه نمی‌داشت، تاریخچه از یک ثبتِ «وضعیت قبلی کارت» با زمان نامشخص شروع می‌شود؛ اتفاقات گذشته حدس زده نمی‌شوند. سابقه، Undo و بایگانی در خروجی JSON هم حفظ می‌شوند. سقف هر کارت ۵۰۰ رویداد است؛ در رسیدن به سقف، تغییر متوقف و پیام روشن نشان داده می‌شود.

## قواعد

- دریافت اولیه نصف دقیق قیمت است. هر دور ۱۰٪ روی بدهی دقیق انباشته می‌آید؛ فقط مبلغ نمایشی و تسویه به نزدیک‌ترین عدد صحیح گرد می‌شود و نیمه رو به بالا است.
- کارت ۲۰۰ در دورهای صفر تا هشت: **۱۰۰، ۱۱۰، ۱۲۱، ۱۳۳، ۱۴۶، ۱۶۱، ۱۷۷، ۱۹۵، ۲۱۴**. مقدار گردشدهٔ دور قبل وارد محاسبهٔ بعد نمی‌شود.
- عبور **دقیق و بیشتر از** قیمت، کارت را وارد آخرین شانس می‌کند. بدهی آن ثابت می‌ماند. تا تعیین تکلیف همهٔ کارت‌های آخرین شانسِ یک بازیکن، دور جدید او ثبت نمی‌شود. زمان‌سنج یا مزایدهٔ خودکار نداریم.
- تسویهٔ مستقل هر کارت، انتقال همراه بدهی و مزایده با شروع یک‌چهارم قیمت موجود است. مزایده و تسویه در سوابق می‌مانند. انتقال آخرین شانس، محدودیت دور را هم به صاحب جدید منتقل می‌کند.
- برای قیمت فرد، پایهٔ دقیق حفظ می‌شود: ۲۰۱ → دریافت ۱۰۱، دور اول ۱۱۱، دور هشتم ۲۱۵؛ شروع مزایدهٔ ۱۵۰ → ۳۸، ۲۰۱ → ۵۰ و ۲۰۲ → ۵۱.
- قیمت صحیح از ۱ تا ۹٬۹۹۹٬۹۹۹٬۹۹۹ است. ارقام فارسی، عربی و لاتین و جداکننده‌های سه‌رقمی معتبر پذیرفته می‌شوند.

## ذخیره و پشتیبان

دفتر در IndexedDB **همان مرورگر و همان آدرس** ذخیره می‌شود. ۵۰ اقدام آخر حتی پس از بازکردن مجدد قابل برگشت‌اند. بازی جدید و بازیابی JSON پس از تأیید، دفتر قبلی را بایگانی می‌کنند؛ بازی جدید نام‌ها را حفظ می‌کند. بایگانی حداکثر ۳۰ بازی دارد و در پرشدن، اقدام جایگزینی متوقف می‌شود. سقف هر بازی ۵۰۰ کارت است.

«خروجی JSON» فایل واقعی برای پشتیبان یا انتقال می‌سازد. «بازیابی JSON» نسخه، مالک، شناسه‌ها، وضعیت و اعداد را کنترل می‌کند و خلاصهٔ فایل را پیش از تأیید نشان می‌دهد. پاک‌کردن دادهٔ سایت یا حالت خصوصی ممکن است داده را از بین ببرد. هیچ حساب، موجودی پول، دیتابیس ابری یا همگام‌سازی گوشی‌ها وجود ندارد.

در دو تب، تراکنشِ مقایسهٔ revision و نوشتن، تغییر ناسازگار را رد می‌کند. تغییر ذخیره‌نشده واضح می‌ماند و می‌توان از آن خروجی گرفت، دوباره ذخیره کرد یا با تأیید نسخهٔ آخر را خواند. دادهٔ خراب خودکار با بازی خالی جایگزین نمی‌شود.

پوسته، فونت‌ها و آیکون‌ها با service worker ذخیره می‌شوند؛ پس از آماده‌شدن، آدرس با قطع شبکه هم باز می‌شود. به‌روزرسانی برنامه وسط عملیات reload اجباری نمی‌کند؛ پس از بسته‌شدن تب‌های قدیمی فعال می‌شود. دادهٔ دفتر خارج از cache برنامه است.

## دفتر قدیمی

کلید `monopoly-mortgage-v1` فقط روی همان origin قابل خواندن است. اگر دفتر جدید وجود نداشته باشد، raw قدیمی محفوظ می‌ماند و مهاجرت یک بار انجام می‌شود؛ کلید قدیمی حذف نمی‌شود. فایل HTML مرجع، بازی ذخیره‌شدهٔ شما نیست.

JSON قدیمی را هم می‌توان بازیابی کرد. مدل ثابت قدیمی به `legacy-simple` قفل‌شده تبدیل می‌شود، نه بهرهٔ مرکب عطف‌به‌ماسبق. دور مؤثر قدیمی به ۸ یا ۱۱ محدود و دور خام ثبت می‌شود؛ مبلغ paid و شناسه‌ها حفظ و زمان‌های ناشناخته `null` می‌مانند. بازی تازه همیشه مرکب است.

برای بازیابی از آرتیفکت قبلی، همان صفحه و مرورگری را که بازی در آن بوده باز کن. اگر امکان خروجی وجود ندارد، در ابزار توسعهٔ همان صفحه مقدار `localStorage.getItem('monopoly-mortgage-v1')` را در یک فایل `.json` ذخیره کن و اینجا بازیابی کن. دادهٔ localhost، فایل محلی، Preview و Production به‌طور خودکار جابه‌جا نمی‌شود.

## توسعه و بررسی

Node.js ۲۲٫۱۲ یا بالاتر؛ یک package manager و lockfile npm:

```sh
npm ci
npm run dev
npm test
npx playwright install chromium
npm run build
npm run test:browser
```

Build در `dist` تولید می‌شود؛ Vercel همین پوشه را ارائه می‌کند. ساختار Vite و JavaScript ماژولار است. منطق دقیق و چرخهٔ وضعیت در `src/domain.js`، ذخیره و اعتبارسنجی در `src/storage.js` و رابط در `src/main.js` قرار دارند. مرجع اولیهٔ تغییرناپذیر در `reference/` است و به سایت کپی نمی‌شود.

برای آزمون انتشار با پروفایل مصنوعی و مستقل: `PLAYWRIGHT_BASE_URL` را روی آدرس هدف تنظیم کن و `npm run test:browser` را اجرا کن. وضعیت واقعی اجراها و انتشار در `STATUS.md` و سناریوها در `docs/ACCEPTANCE.md` نوشته می‌شوند.
